## 2. Орчны урхи — бодитоор тохиолдсон

Дараах бүхэн **энэ төсөл дээр үнэхээр тохиолдсон**. Ижил урхинд хоёр дахин
орохгүйн тулд бичив.

### 2.1 Windows консол — кирилл/япон хэвлэвэл унана
Python-аас `print()`-ээр кирилл эсвэл кана хэвлэвэл `UnicodeEncodeError:
'charmap' codec` гарч скрипт **тасалдана** (cp1252). Хэдэн ч удаа тохиолдсон.

**Шийдэл:** скриптийн гаралтыг зөвхөн **латинаар** бич. Кирилл/япон
харах шаардлагатай бол файлд бичээд тусад нь `cat`-аар үзнэ.

### 2.2 Bash heredoc урвуу зураасыг эвддэг
`bash -c` дотор heredoc-оор Python бичихэд `\n`, `\\u`, `\+`, `\s` зэрэг
**эвдэрдэг**. Үүнээс болж `test_answers.js`-д жинхэнэ шинэ мөр орж
`SyntaxError: Invalid or unexpected token` гарсан. Мөн `SyntaxWarning:
invalid escape sequence` гарч байсан.

**Шийдэл:** урвуу зураас агуулсан ямар ч зүйлд (regex, `\n`, Windows зам)
Bash-ийн оронд **Write/Edit хэрэгсэл** ашиглана.

### 2.3 Supabase публик түлхүүр RLS-ийг тойрдоггүй — АЛДАА ЧИМЭЭГҮЙ
`sb_publishable_…` түлхүүрээр REST-ээр хүснэгт уншихад **алдаа гардаггүй**,
зүгээр л `[]` буцна. GitHub Action «амжилттай» дуусаад «шинэ санал алга» гэж
бичсэн — 30 минут шалтгаан хайлаа.

**Шийдэл:** `feedback-to-issues.yml` одоо түлхүүрийн **хэлбэрийг** шалгаж
(`eyJ` / `sb_secret_` / `sb_publishable_`) публик түлхүүр дээр тодорхой
мессежээр зогсдог. Түлхүүр өөрөө логт хэзээ ч гарахгүй.

### 2.4 GitHub Secrets — хуулахад зай/шинэ мөр ордог
`SUPABASE_URL` дотор санамсаргүй зай орсноос `curl: (3) URL rejected:
Malformed input to a URL function` гарсан. Логт нууц нь `***` тул шалтгаан
харагдахгүй.

**Шийдэл:** workflow одоо `tr -d '[:space:]'`-ээр цэвэрлэж, төгсгөлийн `/`-ыг
хасна.

### 2.5 `set -e` + `[ тест ] && команд`
```bash
[ "$COUNT" -eq 0 ] && exit 0      # ← COUNT != 0 үед бүхэл мөр 1 буцаана
```
`set -e`-тэй бол ажил тэр дор нь **тасалдана**. Хоёр газар байсан.

**Шийдэл:** бүтэн `if … then … fi` бич.

### 2.6 GitHub Pages нь Git LFS-ийг ЗАДАЛДАГГҮЙ
LFS-д тавьсан дууны файлын оронд **заагч текст** файлыг өгдөг. Дуу огт
гарахгүй. Энэ нь GitHub-ийн албан ёсоор хүлээн зөвшөөрсөн хязгаарлалт.

**Шийдэл:** дууг **энгийн git файлаар** хадгална. 72.5 МБ бол ямар ч
асуудалгүй (1 ГБ хязгаартай).

### 2.7 GitHub Pages кэш — `max-age=600`
Файл сольсон ч 10 минут хуучин хувилбар үйлчилнэ.

**Шийдэл:** `index.html` дахь `?v=…` ба `sw.js` дахь `VERSION` **хоёуланг**
хамт сольж push хийнэ. Хоёр газрыг мартвал офлайн кэш хуучин файл өгнө.

### 2.8 Headless Chrome — медиа + `--virtual-time-budget` гацдаг
`--autoplay-policy=no-user-gesture-required`-тай хамт урт budget өгвөл
скриншот **бичигдэхгүй, процесс гацна** (120 сек timeout).

**Шийдэл:** `--headless=new --mute-audio --virtual-time-budget=4000..6000`,
мөн тестийн хуудсанд `HTMLMediaElement.prototype.play`-ыг хиймлээр
`Promise.resolve()` болгож дарж бичнэ.

### 2.9 iframe-ээр аппыг удирдах — хоёр урхи
1. **Cross-origin:** удирдах хуудсыг `file://`-ээс нээвэл `localhost`-ын
   iframe-ийн `document` рүү хандаж чадахгүй, `try/catch` дотор чимээгүй
   унана. → Удирдах хуудсыг **ижил origin**-аас (`http://localhost:8731/…`)
   үйлчлүүлнэ.
2. **`let` нь `window` дээр гардаггүй:** `w.ALL` гэж шалгавал хэзээ ч
   бэлэн болохгүй. → **DOM**-оор шалгана (ж: `#n-vocab` нь `…` биш болсон эсэх).

### 2.10 `[hidden]` ажиллахгүй байсан
`.pane{display:grid}` гэсэн зохиогчийн дүрэм браузерын `[hidden]{display:none}`-ыг
дардаг (author > user-agent). Бүх дэлгэц зэрэг харагдаж байсан.

**Шийдэл:** `app.css`-д `[hidden]{display:none !important}`.

### 2.11 VOICEVOX «AquesTalk風記法» нь `ー`-г хүлээж авдаггүй
`ミャ'ンマー` → `UNKNOWN_TEXT: ー`. Уртатгалыг **эгшгээр** бичих ёстой:
`ミャ'ンマア`.

**Шийдэл:** `expand_choon()` нь өмнөх морагийн эгшгээр солино. Моралын
тоо хадгалагдах ёстой — эс тэгвэл унах байрлалын индекс гажна.

### 2.14 Монгол Ү/Ө нь Windows-ийн фонтуудад БАЙХГҮЙ
**Serif:** `Georgia` · `Times New Roman` · `Palatino Linotype` ·
`Cambria` · `Constantia`.
**Монспэйс:** `Consolas` · `Cascadia Mono` · `Courier New`.

Бүгдэд нь Ү (U+04AE) ба Ө (U+04E8) дутуу. Хөтөч тэдгээрийг өөр фонтоос
орлуулдаг тул нэг үгийн дунд хоёр өөр загварын үсэг холилдоно —
монспэйс дээр бүр эгнээ ч эвдэрнэ.

**Шийдэл:** `Noto Sans Mono`-г өөрсдөө нийлүүлнэ (11 КБ,
`tools/build_fonts.py`).

**2026-09-21 шинэчлэл:** аппын БҮХ бичиг `Noto Sans JP` болсон.
Тэр нь Ү/Ө-г **агуулна** (`U+04AE-04AF`, `U+04E8-04E9` — Google
Fonts-оос `text=`-ээр шалгаж баталсан), тиймээс `--ui`/`--disp` ч
системийн фонт руу унахаа больсон. Дэд фонтыг үүсгэхдээ япон
тэмдэгт дээр латин+кириллийг ЗААВАЛ нэмнэ (`jp + lc`) — эс тэгвэл
монгол текст чимээгүйхэн Segoe UI рүү буцна.

### 2.15 Google Fonts `text=` нь URL урт бол ЧИМЭЭГҮЙ үл тоогддог
1568 тэмдэгт өгөхөд (URL 14 КБ) огтолсон НЭГ файлын оронд бүтэн фонтыг
**124 хэсгээр** буцаав. Алдаа өгөхгүй — зөвхөн үр дүн нь өөр.

**Шийдэл:** 300 тэмдэгтийн багцаар хүсэлт тавьж, буцах `url()`-ийн тоог
шалгана; 1-ээс олон бол зогсоно.

### 2.21 `background-position`-ын анимаци нь бүтэн дэлгэцийг дахин зурна
GPU-д зөөгдөхгүй тул кадр болгонд repaint болно. Утсан дээр гурван ийм
давхарга зэрэг ажиллаж байхад мэдэгдэхүйц гацдаг.

**Шийдэл:** `transform: translate3d()`. Дэвсгэрийг хавтгайгаар давтаж,
элементийг ЯГ нэг хавтгайн хэмжээгээр зөөвөл заадасгүй давтагдана.
Налуу зураасны хувьд (0,0)→(w,h) шугам нь хоёр тэнхлэгт таардаг.

**Бас:** `vmax` нэгжээр өгсөн давхарга нь утсан дээр дэлгэцээс 3.5 дахин
том талбай зурдаг. `%` нь `#bg`-ийн (дэлгэцийн) хэмжээтэй холбогддог тул
найдвартай. `backdrop-filter`-ийг НЭГ-ХОЁР гадаргуугаас хэтрүүлэхгүй.

### 2.23 Data URI доторх `#` — НЭГ л удаа кодлоно
SVG доторх `url(#gradientId)` лавлагааг `%23` гэж урьдчилан бичвэл
`urllib.parse.quote()` түүнийг дахин кодлож `%2523` болгоно. Градиент
олдохгүй, элемент огт зурагдахгүй — АЛДАА өгөхгүй, зүгээр л хоосон.
Түүхий SVG-д `#` гэж бичээд кодлолтыг нэг удаа хийлгэ.

### 2.24 Шуугиан нь ТОД ИРМЭГТЭЙ хэлбэр өгч чадахгүй
`feTurbulence` нь үргэлж бүдэг, тархай толбо гаргана. Анимегийн үүл,
логотип, дүрс зэрэг ТОДОРХОЙ силуэт шаардсан зүйлийг шуугианаар хийж
болохгүй — зурах хэрэгтэй. Давхарласан тойрог нь нэг силуэт болж
нэгддэг тул овоохой хэлбэрт тохиромжтой.

**Хэмжээний урхи:** үүлний суурийг нэг том тойргоор өгвөл радиус нь
өргөнөөс хамаарч аварга болно. Өндрөөр хэмжигдэх жижиг тойргийн эгнээ
ашигла.

### 2.22 `#bg`-ийн pseudo нь хүүхдүүдээс ДООГУУР зурагдана
`#bg` нь `z-index:0`-тэй тул давхаргын хүрээ үүсгэнэ. `::before` нь
`z-index` авахгүй бол `i` хүүхдүүдийн ДООГУУР орно. Борооны зураасыг
дуслын давхарга бүтэн дэлгэцээр угааж байсан шалтгаан энэ.

### 2.20 Маск нь бүтэц өгдөг, ГЭРЭЛ өгдөггүй
`feTurbulence`-ийг зөвхөн `mask-image` болгож ашиглавал ямар хэсэг
харагдахыг л заана — гадаргуу хавтгай хэвээр үлдэж, «будсан» мэт
харагдана. Гурван удаа тааруулсан ч материал бодитой болоогүй.

**Шийдэл:** `feDiffuseLighting` / `feSpecularLighting` нь оролтын
**альфа сувгийг өндрийн зураг** болгон уншиж гэрэл тусгана. Металл, ус
зэрэг эзэлхүүнтэй материалд ЗААВАЛ энэ хэрэгтэй.

Хоёр анхаарах зүйл:
· Гэрлийн өнгө нь дэвсгэрийн өнгөтэй ойрхон бол юу ч харагдахгүй.
  Усны дуслын биеийг БАРААН болгосны дараа л дусал мэт харагдав.
· Гаралтыг data URI болгож хадгалбал хөтөч филтер тооцохгүй —
  нэг удаа растержина.

### 2.19 Хөдөлгөөнийг тодорхой агшинд ЗОГСООЖ зураг ав
`--virtual-time-budget` нь WAAPI нислэгийг санамсаргүй агшинд барина —
дунд нь ч, дууссаны дараа ч байж болно. Тогтвортой зураг авахын тулд:

    d.getAnimations().forEach(a => { a.currentTime = 300; a.pause(); });

CSS шилжилтийн хувьд `*{transition:none !important}` (2.18-ыг үз).

### 2.18 Theme сольсны дараа шууд зураг авахыг БОЛИХ
`button` дээр `transition: background-color .18s, color .18s` байгаа тул
`data-theme`-ийг сольсны дараа авсан зураг **шилжилтийн дунд** байдлыг
барина: товч, гарчиг хар харагдаж, «токен ажиллахгүй» гэсэн ХУУРАМЧ
дүгнэлт төрүүлнэ. `--virtual-time-budget` энэ шилжилтийг найдвартай
дуусгадаггүй.

**Шийдэл:** зураг авах эсвэл хэмжихийн өмнө iframe дотор
`*,*::before,*::after{transition:none !important}` хэвлэнэ. Эргэлзвэл
`getComputedStyle`-аар токеныг ШУУД хэмж — зургаар бүү дүгнэ.

### 2.17 Headless Chrome-ийн цонх 500px-ээс НАРИЙН болдоггүй
`--window-size=430,1000` гэж өгсөн ч `innerWidth` нь **500** хэвээр
(Windows дээр шалгав: 380 → 500, 430 → 500, 500 → 500). Зураг нь
хүссэн өргөнөөр хайчлагдана — үр дүнд нь **хуудас баруун талаасаа
тасарсан мэт харагдана**. Утсан дээр халилт гарлаа гэж андуурч
болзошгүй; бодитоор халилт БАЙХГҮЙ байв (`scrollWidth 415 = clientWidth 415`).

**Шийдэл:** утасны өргөнийг шалгахдаа дээд түвшний цонх биш,
**хүссэн өргөнтэй `iframe`**-ийг ≥500px цонх дотор ашиглана.
`--force-device-scale-factor=2` нь энэ хайчлалыг илүү ил болгодог тул
эргэлзвэл түүгээр давхар шалга.

### 2.29 `esc()` нь ХАШИЛТЫГ орлуулдаггүй — атрибутад ХЭРЭГЛЭХГҮЙ
`esc()` нь зөвхөн `&` `<` `>` гурвыг орлуулна. Атрибутын дотор тавивал
`id="A" onmouseover="…"` гэсэн утга тэндээс ГАРЧ жинхэнэ атрибут
үүсгэнэ. Браузер дотор баталсан (2026-09-11):

    data-a="A" onmouseover="window.__x=1" y=""   ← DOM-д атрибут болов

**Дүрэм:** элементийн ДОТОР `esc()`, АТРИБУТАД `escA()`.

**Тест бичихэд:** HTML МӨРӨӨР бүү шалга. `onmouseover=&quot;` гэсэн
текст нь аюулгүй, `onmouseover="…"` гэсэн атрибут нь аюултай — хоёул
мөрөнд `onmouseover=` гэж харагдана. `el.attributes`-ыг үз.

### 2.30 `jsonb_set()`-ийг ДАВТАЖ дуудвал O(n²)
`jsonb_set` нь баримтыг бүхэлд нь ДАХИН угсардаг. Түлхүүр бүрд дуудвал
хэмжээ өсөхөд квадратаар удаашрана. Хэмжив: **2000 карт → 13.17 сек**,
тэр хугацаанд `for update` түгжээг барина.

**Шийдэл:** ялах бичлэгийг НЭГ `jsonb_object_agg`-аар цуглуулаад `||`-оор
нийлүүлнэ (баруун тал давамгайлдаг). O(n log n).

### 2.31 `(v ->> 'x')::int` нь хорлонтой jsonb дээр ГҮЙЛГЭЭГ унагана
`{"n":"abc"}` ирвэл cast алдаа өгч бүх гүйлгээ унана. `jnum(jsonb)`
туслах функц ашиглана: `jsonb_typeof(v) = 'number'` эсэхийг шалгана.

### 2.52 «AquesTalk風記法» нь ТОЛЬ БИЧИГ ХЭРЭГЛЭХГҮЙ — бөөс は нь «ha» болно
`build_audio.py` нь номын өргөлтийн тэмдэглэгээг катакана болгоод
`/accent_phrases`-д **`is_kana=true`**-аар өгдөг. Тэр горим нь кана
бүрийг **үсгээр нь** уншиж, морфологийн задлал хийхгүй. Үр дүнд нь
бөөсний `は` нь `wa` биш `ha` болно:

    こんばんは○ -> コンバンハ' -> ko N ba N **ha**    буруу
    зөв нь                        ko N ba N **wa**

Хэрэглэгч чихээрээ олсон («konbanha»). Хөдөлгүүрээс фонемийг шууд
уншиж баталсан.

**Шийдэл:** `fix_particles()` — тэмдэглэгээ үүсгэхийн өмнө үгийг
хөдөлгүүрийн **толь бичгээр** уншуулж (`is_kana` БАЙХГҮЙ), `ハ/ヘ` нь
`wa/e` болж уншигдсан бол `ワ/エ` болгоно. `を` нь `is_kana` горимд ч
`o` болдог тул хөндөхгүй.

**Хамгийн чухал нарийн ялгаа — тольд ЮУ өгөх вэ:**

| Асуулга | `母` | `歯` | `18` | `こんばんは` | Зөв |
|---|---|---|---|---|---|
| **Ханзаар** (`jp`) | ha ha | ha | ju u ha chi | ko N ba N wa | **19/19** |
| Канагаар (`はは`) | wa wa | wa | ju u wa chi | ko N ba N wa | 8/19 |

Ганц кана мөр өгвөл хөдөлгүүр **эхний `は`-г бөөс гэж андуурна**.
Ханз нь утгыг тодруулдаг. Эхлээд канагаар асууж 33 үг «зассан» —
24 нь БУРУУ байв (`母 → ワワ`, `歯 → ワ`, `8月 → ワチガツ`). Ханзаар
шилжүүлэхэд 9 үг үлдсэн, бүгд зөв.

**Гурван хамгаалалт, гурвуулаа бодит алдаанаас төрсөн:**
1. **Мора тоо зөрвөл хөндөхгүй.** `日本へ`-г толь `にっぽんへ` (5 мора)
   гэж уншина, тэмдэглэгээ нь `にほんへ` (4) — байрлалаар тулгах
   найдваргүй.
2. **Бичигдээгүй бөөсийг уншихгүй.** `～ha` (гектар, ЛАТИН) дээр толь
   `ヘ`-г `エ` болгож `エクタアル` гаргасан. `は` нь `jp`-д
   **бичигдсэн** байж л `ワ` болно.
3. **`、` тусгаарлагчтай бол нийлүүлэхгүй.** `／` нь ӨӨР ХЭЛБЭР гэсэн
   үг (`はし／おはし`) — нийлүүлбэл `jp`-тэй тэнцэхгүй. Бусад
   тусгаарлагч (зай, `△`) нь нэг хэллэгийн үргэлжлэл тул нийлүүлнэ
   (`昨年は いろいろ…`).

**Регресс:** `tools/test_audio.py` — 23 шалгуур. Хөдөлгүүр асаалттай
байх шаардлагатай. Эсрэг чиглэлийн шалгуур заавал байна: `母`, `歯`,
`笹の葉`, `発売中` нь `ha` ХЭВЭЭР үлдэх ёстой.

**Сөрөг тест хийсэн:** `fix_particles`-ыг унтраахад бөөсний 3 тохиолдол
унаж, хяналтын `はな` цэвэр хэвээр үлдэв.

### 2.53 «Агуулга нь өөрчлөгдөхгүй» гэсэн кэш нь НЭГ УДАА зөрчигдөж болно
`sw.js`-ийн `media-v1` кэш нь «mp3 бүр id тутамд нэг, агуулга нь хэзээ ч
өөрчлөгдөхгүй» гэсэн таамаг дээр суурилдаг тул хувилбартай холбоогүй.
§2.52-ын засвар 12 бичлэгийн **агуулгыг** өөрчилсөн — хуучин
хэрэглэгч «konbanha»-г үүрд сонсох байсан.

**Шийдэл:** кэшийг бүхэлд нь хаяхгүй (149 МБ дахин татна). `STALE_MEDIA`
жагсаалт — `activate` дээр ЗӨВХӨН тэдгээрийг `cache.delete`-ээр хасна.
Дахин зассан тохиолдолд жагсаалтыг **солино**, нэмэхгүй.

**Дүрэм:** дууны агуулга өөрчлөх бүрд `VERSION` ба `index.html`-ийн
`?v=` (6 газар) хоёрыг хамт өргөж, `STALE_MEDIA`-г шинэчил.

### 2.56 Анги — нэр ба код хаана байдаг, яагаад
Багш даалгавар өгөөд сурагчид хийж байгаа эсэхийг харах зорилготой
(2026-09-22). Хоёр анги: **MICA** (`mica`) ба **Наран** (`c2`). Нэг хүн
хоёуланд, эсвэл «Бусад».

**Ангийн нэр КЭШЛЭГДДЭГ** (`irodori.classes.v1`). Урьд нь зөвхөн тохируулах
дэлгэц нээхэд шинэчлэгддэг байсан тул серверт «2-р анги» → «Наран»
солиход аль хэдийн элссэн сурагч хуучин нэрийг ҮҮРД харах байв. Одоо
апп нээгдэх бүрд (`refreshClassNames`) ба ангийн дэлгэц серверийн нэрээр
шинэчилнэ. Нэр солих: `update public.classes set name = '…' where id = '…';`
+ `classes-seed.sql`-ийг ч засна — эс тэгвэл дахин ажиллуулахад нэр буцна.

| Юу | Хаана | Яагаад |
|---|---|---|
| Ангийн **КОД** | Supabase `classes` + `00-admin/secrets/irodori-vocab/` | Репо ба сайт **нийтэд нээлттэй** — кодыг `SUPABASE.sql`-д бичвэл хэн ч уншина |
| Нэр | Төхөөрөмж (`irodori.me.v1`); серверт ЗӨВХӨН ангид элссэн үед | `SUPABASE.sql`-ийн зарчим «нэр ч үгүй» байсан — анги нь ганц үл хамаарах зүйл |
| Гишүүний id | `me.id` — `devId`-ээс ТУСДАА | Хэрэглээний нэргүй тоог (ping) нэртэй холбохгүй |

**«Бусад»-ын нэр ХЭЗЭЭ Ч илгээгдэхгүй.** Ангиас «Бусад» руу шилжихэд
серверийн мөрийг устгах хүсэлт ч ХООСОН нэртэй явна; түүнээс хойш сүлжээ
огт дуудагдахгүй (`me.srv` хоосон). Тест §28 хоёуланг шалгадаг.

**Таах хязгаар — яагаад цагт 20 биш 50.** Багш кодоо сольход анги бүх
сурагчийн апп ХУУЧИН кодоор НЭГ удаа оролдоно. 30 сурагчтай ангид 20
нь шууд түгжих байв. Клиент татгалзсан кодыг ДАХИН илгээхгүй (`me.lost`)
— эс тэгвэл дасгал бүрд оролдож, хязгаарыг бүгд хамтдаа дуусгана.

**Код солигдоход анги ЧИМЭЭГҮЙ алга болж байсан** (тест олсон, засав).
`refreshKlass()` эхлээд `memberSync()` дууддаг — тэр нь хуучин кодыг
хаячихаад, дараа нь жагсаалт хоосон, мэдэгдэлгүй гардаг байв. Мөн
дэвсгэрт хаягдвал «Анги» цэснээс алга болж, шалтгааныг ХААНААС ч
харах аргагүй. Одоо `me.lost`-д бичиж, ангийн дэлгэц ба Тохиргооны
картад «код солигдсон» гэж хэлнэ; дахин элсэх эсвэл «Бусад» сонгоход арилна.

**«Өнөөдөр» ба «дараалан» нь хуучирдаг.** Сервер нь `day` (клиентийн
өдрийн дугаар) хадгална; жагсаалтыг харж буй төхөөрөмж өөрийн өдөртэй
тулгана — өчигдөр 20 үг хийсэн хүн «өнөөдөр 20» гэж харагдахгүй.
Сервер UTC, хэрэглэгчид UTC+8 тул шийдвэр КЛИЕНТЭД.

**Хэрэгжүүлэх дараалал:** `SUPABASE.sql` → `classes-seed.sql` → апп
түлхэх. Эсрэгээр хийвэл бүх хэрэглэгч нэр асуух дэлгэц дээр зөвхөн
«Бусад»-ыг харж, дараа нь дахин засах шаардлагатай болно.

### 2.60 Ангийн даалгавар — тоолох дүрэм ба нууцлал
Анги бүр НЭГ даалгавартай (`classes.task`):
`{"lessons":[1..8], "n":20, "since":"2026-09-22"}` = L1–L8-ын шалгалтын
асуултаас 20 ӨӨР асуулт. Одоогоор эзэн SQL-ээр тавина
(`00-admin/secrets/irodori-vocab/classes-seed.sql`-ийн төгсгөлд).

**Тоолол:** давхардалгүй асуулт (`exHist` нь асуулт тутамд СҮҮЛИЙН
хариулт), `since`-ээс хойш, «чадсан/чадаагүй»-н аль нь ч. Сервер
(`class_roster`) ба клиент (`taskDoneLocal`) ЯГ ижил дүрмээр боддог —
нэгийг өөрчилбөл нөгөөг ч.

**Өдрийн дугаар:** клиентийн `today()` = орон нутгийн огнооны 1970-оос
хойшх өдөр. Сервер `'1970-01-01'::date + day`-ээр огноо болгож `since`-тэй
тулгана — цагийн бүс хамаарахгүй.

**Нууцлал:** `members.exam` ТҮҮХИЙГЭЭР клиент рүү буцахгүй; roster зөвхөн
`task_n`/`task_ok`. «Бусад» бол `p_exam: null`.

**Гарын үсэг солигдоход:** `member_put`-ийн хуучин 8 параметрт хувилбарыг
`drop` хийсэн. Клиентийг SQL-ээс ӨМНӨ түлхвэл шинэ апп 9 параметртэй
функц олохгүй → гишүүний тоо шинэчлэгдэхээ болино. **Дараалал: SQL →
апп.** Эсрэгээр — хуучин апп шинэ SQL-тэй ажиллана (default).

**Тестийн урхи:** нэг `c.ev` доторх `el.querySelector(...).textContent`
нь эвдрэлийн үед `null`-аас болж БҮХ шалгалтыг унагаж, бусад эвдрэлийг
далдалсан. Хайлт бүрийг null-д тэсвэртэй болгосны дараа гурван эвдрэл
бие даан баригдав.

### 2.65 Тест ЖИНХЭНЭ сервер рүү чимээгүй очиж болно
`examSetup()` нь `loadClassList()` дууддаг. Тест `rpc`-г үлдээчихвэл
амьд Supabase-аас ангийн ЖИНХЭНЭ даалгавар ирж, тестийн тавьсан
нөхцлийг ДАРНА («дуусгасан даалгавар дээр автоматаар эхлэхгүй» гэсэн
шалгуур ийм учраас унасан).

**Дүрэм:** ангийн/даалгаврын аливаа урсгал шалгахдаа `rpc`-г ЗААВАЛ
орлуул. Сүлжээ рүү явсан тест нь удаан, тогтворгүй, бас амьд өгөгдлөөс
хамаарна.

### 2.64 ХУВААЛЦСАН мөрийн бүх талбар УУСАХ ёстой
Утас, компьютер нэг гишүүний мөр хуваалцдаг. Тэр мөрийн талбар бүрд
«хоёр тал нь өөр өөр утгатай байвал яах вэ» гэсэн хариулт хэрэгтэй:

| Талбар | Дүрэм |
|---|---|
| `name` | сүүлд ЗАССАН нь (§2.63) |
| `exam` | УУСГАНА — асуулт тутамд сүүлийн өдрийнх |
| `seen`/`learned`/`today`/`streak` | сүүлд бичсэн нь (явц нь өөрөө синкддэг тул аль ч төхөөрөмжөөс ижил тоо гарна) |

**Бодит алдаа:** `exam`-ыг ДАРЖ бичдэг байсан. Компьютер дээр даалгавраа
хийгээд утсаараа аппаа нээхэд утасны ХООСОН түүх серверийнхийг бүрэн
устгаж байв (хэрэглэгч «0 харагдаж байна» гэж мэдээлэв).

Уусгасан үр дүнг `member_put` буцаадаг тул клиент ч өөр дээрээ тавина
— хоёр төхөөрөмж дээр ижил явц харагдана.

**Дүрэм:** хуваалцсан мөрөнд ШИНЭ талбар нэмэх бүрд «уусгах уу, дарах
уу» гэдгийг ЗААВАЛ шийд. Анхдагчаар дарах нь өгөгдөл алдагдуулна.

### 2.63 Хуваалцсан мөрийн НЭР — «сүүлд зассан» нь ялна
Утас, компьютер нэг гишүүний мөр хуваалцдаг. Нэр нь төхөөрөмж тус бүрд
хадгалагддаг тул хамгийн сүүлд СИНК хийсэн нь бичдэг байв — хоёр нэр
ээлжлэн солигдоно.

Зөв дүрэм нь «сүүлд СИНК хийсэн» биш **«сүүлд ЗАССАН»**: `me.nameAt`
(клиентийн цаг, мс) -> `p_name_at`. Сервер `name_at`-ийн ИХИЙГ барьж,
хүчинтэй нэрийг буцаана; клиент түүнийг аваад тавина. Ингэснээр
дараалал хамаарахгүй, хоёр төхөөрөмж НЭГ утга дээр нийлнэ.

Хуучин клиент `name_at = 0` илгээдэг тул хэзээ ч дарж бичихгүй.

**Анхаар:** `member_put`-ийн хариунд `name` түлхүүр нэмэгдсэн. Тэр нь
ангийн id БИШ — `me.srv`-г бодохдоо хасна (хэрэглэгчийн нэр «ok»
байвал анги мэт тоологдох байсан).

### 2.62 Багшийн эрх — тусдаа код, даалгаврын хугацаа
Анги бүр ХОЁР кодтой: `code` (сурагч, 4 орон) ба `tcode` (багш, 6 орон).
`class_join` нь `'ok'` / `'teacher'` гэж ялгана. Багш:
- `class_roster`-ыг харна (`role: 'teacher'`),
- `task_set`-ээр даалгавар тавина,
- **гишүүн БОЛОХГҮЙ**: `member_put` зөвхөн `'ok'` үед мөр үүсгэнэ.
  Клиент нь багшийн кодыг `me.teach`-д хадгалдаг (`me.codes`-д БИШ) тул
  `memberSync` огт сүлжээ дуудахгүй — нэр нь серверт очихгүй.

**Хугацаа:** `task.until = since + days`. Тоололд `since..until`
хоорондох хариулт л орно — дуусахад хувь ЗОГСОНО. Сервер
(`class_roster`) ба клиент (`taskDoneLocal`) ижил дүрэмтэй; нэгийг
өөрчилбөл нөгөөг ч.

**Хоёр алдааг тест барив:**
1. `task_set` нь сурагчийн кодод `{'status':'ok'}` буцааж байв —
   бичихгүй ч клиент «хадгалагдлаа» гэж ойлгоно. Одоо `'denied'`.
   *Дүрэм: татгалзлын код амжилтын кодтой ХЭЗЭЭ Ч давхцаж болохгүй.*
2. `refreshMe()` дотор багшийн салбарт `return` бичсэнээс цэсний «Анги»
   мөр шинэчлэгддэггүй байв. *Дүрэм: олон зүйл шинэчилдэг функцийн
   ДУНД `return` бичихгүй.*

### 2.61 Гишүүний id — синкийн кодоос (утас + компьютер = нэг хүн)
Төхөөрөмж тутмын санамсаргүй id нь нэг хүнийг ангид ХОЁР удаа
гаргадаг байв. Одоо синктэй бол `SHA-256('irodori:' + syncCode)`-ийн
эхний 22 тэмдэгт. Кодыг ТҮҮХИЙГЭЭР илгээхгүй — код бол явцын түлхүүр.

**Хамгийн чухал нарийн ялгаа:** id солигдоход (код холбох/солих/салгах)
ХУУЧИН мөрийг устгах ёстой (`me.sent`). Үгүй бол жагсаалтад хөдөлгөөнгүй
хуучин нэр мөнхөд үлдэнэ. `syncIdentityChanged()` нь гурван товч дээр ч
дуудагдана.

`crypto.subtle` нь зөвхөн аюулгүй контекстэд (https, localhost) байдаг —
байхгүй үед тогтмол FNV хэшээр. Зорилго нь нууцлал биш, ИЖИЛ id.

### 2.57 Тест бичих урхи — энэ өдөр гурвуулаа тохиолдсон
1. **`saveProgress()` нь localStorage-аас БУЦААЖ нэгтгэдэг** (өөр
   табаас хамгаалах). Тест дотор `progress = {}` гэхэд эхний `grade()`
   өмнөх тестүүдийн 42 үгийг эргүүлж авчирна. → `localStorage.removeItem(KEY_P)`
   хийж, дараа нь буцааж тавь (§27).
2. **`sed` глобал солилт** өөр тестийн хувьсагчийг эвдсэн (`st` → `sw`).
   → Засахаас өмнө `git diff`-ээр шалга; хувьсагчид ӨВӨРМӨЦ нэр өг.
3. **Тестийн сервер асаагүй** байхад бүх тест [1]-д `ALL is not defined`
   гэж унана — `&&` гинжний эхний алхам унавал сервер асахгүй.
   → Сервер асаахыг синтакс шалгалтаас ТУСАД нь хий.

### 2.55 Нэг алдааг ХОЁР газар засах ёстой байсан — өдрийн зорилт
§2.51-д дасгалын толгойн тоолуурыг («21/20») зассан. Гэвч ЯГ ИЖИЛ
алдаа **өдрийн зорилтод** үлдсэн байв: `tickDay()` нь `grade()` дотор
байсан тул **хариулт бүрд** өсдөг. Алдсан карт мөчлөгийн төгсгөлд
эргэж ирээд дахин `grade()` дуудагддаг тул нэг үгийг 5 удаа давтвал
5 гэж бүртгэгддэг.

Хэрэглэгч мэдээлсэн: 20 үгийн **нэг** дасгалын дараа **«109/20»**.

**Эхний засвар ХАНГАЛТГҮЙ байсан.** `tickDay(counts)` болгож ДУУССАН
КАРТ-аар тоолуулав — «109/20» арилсан ч хэрэглэгч дараа нь **«40/20»**
гэж мэдээлэв: ижил үгийг дахин судлахад дахин нэмэгдэж байв.

**Эцсийн шийдэл:** `days.ids` — өнөөдөр судалсан үгийн **id-уудыг**
цуглуулж, тоог түүнээс гаргана.

| Юу | Хэзээ | Яагаад |
|---|---|---|
| **Цуврал** (`streak`) | хариулт БҮРД | «өнөөдөр давтсан уу» гэдэг асуулт. Бүгдийг буруу хариулсан ч давтсанд тооцно |
| **Зорилт** (`n = ids.length`) | шинэ id нэмэгдэх үед | нэг үг өдөрт НЭГ л удаа |

**Хуучин өгөгдлийг СЭРГЭЭНЭ** (`recoverDayIds`). `grade()` нь
`p.d = today() + BOXES[p.b]` гэж бичдэг тул

```
p.d - BOXES[p.b] === today()   ⇔   тэр үгийг ӨНӨӨДӨР судалсан
```

`d` ба `b` хоёр ҮРГЭЛЖ хамт бичигддэг тул хуурамч тохироо гарахгүй.
Ингэснээр шилжилт нь өнөөдрийн бодит ажлыг хаялгүй, зөвхөн
ДАВХАРДЛЫГ л арилгана (тестээр: 40 → 7).

**Таб хооронд нэгтгэх нь НЭГДЭЛ (union).** Урьд нь «том тоог нь ав»
байсан — id-тай болсон хойно тэр нь нөгөө табын үгсийг хаяна.

**Дүрэм — хоёр удаа сурсан:**
1. «Хэд хийсэн» гэсэн тоо аппад ХЭД БАЙГААГ шалга. §2.51-ийг зассан
   үед энэ хоёр дахь тоолуурыг олоогүй.
2. «Хариулт биш карт» гэдэг нь **хангалтгүй** нарийвчлал байв. Зөв
   асуулт нь «хэрэглэгч юуг тоолж байна гэж бодож байна вэ» — энэ
   тохиолдолд ӨӨР ӨӨР ҮГ.

**Регресс:** `tools/test_ui.js` §26 — 10 шалгуур (шилжилтийг оруулаад).
Сөрөг тест: давхардал таслагчийг хасахад `goalAfterRepeat` нь 20-ийн
оронд **40** гарч, хэрэглэгчийн мэдээлсэн тоог ЯГ давтав.

### 2.54 Тестийн сервер нь СЕССИЙН ДАРАА ч амьд үлддэг
`python -m http.server 8765 &` нь терминал хаагдсаны дараа ч ажилласаар
байна. 2026-09-22-нд **36 орхигдсон процесс** хуримтлагдсан байв.

### 2.51 ХАРИУЛТ тоолох ба КАРТ тоолох хоёр ЗӨРНӨ
Дасгалын толгойн `done` нь хариулт бүрд өсдөг байв. Алдсан карт
мөчлөгийн төгсгөлд эргэж ирдэг тул хариултын тоо картын тооноос
ДАВНА: 20 картын нэгийг алдвал «21/20» гэж гарна. Браузерт давтав —
5 картад `6/5`.

**Шийдэл:** `done` нь ЗӨВ хариулсан (= мөчлөгөөс гарсан) картыг
тоолно. Мөчлөг нь бүх карт зөв хариулагдсан үед л хоосордог тул
`done` → нийт тоо яг таарна. `okN`/`ngN` нь ХАРИУЛТЫН тоо хэвээр —
дүгнэлтийн хувь тэднээс бодогддог.

**Дүрэм:** «хэд хийсэн» гэсэн тоог харуулахдаа ХАРИУЛТ уу, ЗҮЙЛ үү
гэдгээ шийд. Давтан асуудаг систем дээр хоёр нь хэзээ ч тэнцэхгүй.

### 2.48 `toKana()` нь ЛАТИНД зориулагдсан — япон оролтыг хаядаг
`toKana(src)` нь `[^a-z\-']` бүхнийг устгадаг тул `ねこ` → `''`.
`checkTyped()` нь ЗӨВХӨН түүгээр дамжуулж байсан учир **япон гараар
зөв бичсэн хариултыг «буруу» гэж тэмдэглэдэг байв**. Браузерт баталсан:
`ねこ`, `ネコ`, `おちゃ`, `せんせい` — бүгд татгалзаж, зөвхөн `neko`
хэлбэр л ажиллаж байв.

**Шийдэл:** `set.has(normKana(raw))`-ыг НЭМЭВ. `answerSet` нь
`normKana`-гаар хэвийн болгож хадгалдаг тул оролтыг мөн тэгж хэвийн
болгоход катакана→хирагана хөрвөж, ханз хэвээр дамжина.

**Дүрэм:** оролт хүлээн авдаг функцийг ГАДААД гараар туршиж үз —
латин туршилт л бичвэл ийм алдаа мөнхөд үлдэнэ.

### 2.49 Гүйлтийн тэмдэг нь ӨГӨГДӨЛД ч хэрэгтэй

**Шийдэл:** `progGen` тоолуур — устгал бүрд ахиулж, синк буцахдаа
шалгана (§2.36-ийн тэмдгийг ӨГӨГДӨЛД хэрэглэсэн хувилбар).

### 2.50 Кана «сонсоод таах» — ИЖИЛ дуутай хос

### 2.45 `show()` дотор `screen` нь ЭРТ дарагддаг

**Дүрэм:** `show()` дотор өмнөх дэлгэцийг хэрэглэх бол функцийн ЭХЭНД

### 2.44 `AudioContext`-ыг УРЬДЧИЛАН үүсгэвэл гар утсан дээр гацна
Хэрэглэгчийн үйлдлээс ӨМНӨ `new AudioContext()` хийвэл `suspended`
төлөвт үүсч, дараа нь `resume()` дуудахгүй бол дуу гарахгүй. Тиймээс
контекстыг ЭХНИЙ хэрэгцээнд нь (хариулт өгөх үед — тэр нь өөрөө
үйлдэл) үүсгэнэ. Дээрээс нь таб далд болох үед хөтөч түүнийг
унтраадаг тул дуудалт бүрд `state === 'suspended'` эсэхийг шалгана.

**Мөн:** осциллятор эхлэх/дуусахад дууны далайцыг огцом тасалбал
чанга «клик» сонсогдоно — богино дугтуй (`exponentialRampToValueAtTime`)
заавал тавина. `exponential`-д ТЭГ утга өгч болохгүй, `0.0001`-ээс
эхэлнэ.

**iOS:** `navigator.vibrate` нь Safari-д БАЙХГҮЙ. Чичиргээг заавал
`if (navigator.vibrate)` гэж хамгаална, мөн хэрэглэгчид ил хэл —
эс тэгвэл «ажиллахгүй байна» гэсэн санал ирнэ.

### 2.43 Шилжилттэй элементийг `hidden`-ээс ШУУД нээж болохгүй
`hidden` нь `display:none`. Түүнийг аваад тэр дор нь `transform`-ыг
эцсийн утгад нь тавибал браузер завсрын төлөвийг зурахгүй — элемент
шууд байрандаа **үсэрч** гарч ирнэ, шилжилт огт харагдахгүй.

**Дүрэм:** хоёр алхам. `hidden`-ийг авч, `requestAnimationFrame`
дотор `open` ангиа нэм. Хаахдаа эсрэгээр: `open`-ыг аваад, шилжилтийн
хугацаа өнгөрсний ДАРАА `hidden`. `transitionend` дээр найдаж
болохгүй — `prefers-reduced-motion` үед тэр үйл явдал хэзээ ч ирэхгүй
тул элемент мөнхөд нээлттэй үлдэнэ. Таймер найдвартай.

**Мөн:** `display:flex` нь браузерын `[hidden]{display:none}`-ийг
дардаг (§2.10-тай ижил урхи) тул `[hidden]{display:none !important}`
шаардлагатай.

### 2.40 Гараар дарах ба системийн сонголт — ХОЁР сонгогч хэрэгтэй
Цайвар/бараан нь `prefers-color-scheme`-ээр системийг дагаж байсан.
Дээр нь гар удирдлага нэмэхэд `@media`-гийн дотор байгаа барааныг
хэрэглэгч «цайвар» гэж сонгоход ДАРЖ БИЧИХ хэрэгтэй болно. CSS нь
media query-г атрибутаар дардаггүй тул:

```css
:root{ /* цайвар */ }
@media (prefers-color-scheme: dark){
  :root:not([data-theme="light"]){ /* бараан */ }
}
:root[data-theme="dark"]{ /* ДАХИН бараан */ }
```

`:not([data-theme="light"])`-гүй бол систем бараан үед «цайвар»
сонгосон нь ажиллахгүй. CSS блок хуваалцдаггүй тул барааны токенууд
ДАВХАРДАНА — нэгийг нь засвал нөгөөг нь ч зас. `test_ui.js` §4 нь
системийг БАРААН болгож эмуляцлаад «цайвар» сонгоход үнэхээр цайвар
болж байгааг шалгадаг: энэ нь хоёр сонгогчийн шууд нотолгоо.

**Мөн:** `meta[name=theme-color]`-ийн `media` атрибут нь ЗӨВХӨН
системийн сонголтыг мэднэ. Гараар дарсныг мэдэхгүй тул хөтөч буруу
өнгө үзүүлнэ — JS нь хоёуланг нь бодит өнгөөр дүүргэх ёстой.

### 2.39 Токенжсэн CSS нь БҮХЭЛ загварыг солихыг хямд болгодог
Таван загвар, чимэглэлийг хасаад цайвар/бараан руу шилжихэд өнгөний
ажил нь `:root`-ийн **25 мөр** л байв — бусад 640 мөр CSS хөндөгдөөгүй.
Учир нь өнгө, радиус, зай бүр токеноор дамждаг байсан.

**Дүрэм:** CSS-д хатуу өнгө БИТГИЙ бич. Нэг удаа хатуу бичсэн өнгө нь
бараан горимд чимээгүйхэн эвдэрнэ — тэр газар нь зөвхөн нүдээр л
олдоно. Шинэ дүрэм нэмэхдээ `var(--…)` ашиглаж байгаа эсэхээ шалга.

**Мөн:** `display:block`-ыг `inline-block` болгоход доорх ах дүү
элемент нь блокоос инлайн болж ХАЖУУД нь бичигдэв («дараалсан өдөр»
гэсэн шошго тооныхоо хажууд гарсан). Зөвхөн дэвсгэрийг нь агуулгаар
хумих гэж байвал `width:fit-content` хэрэглэ, `inline-block` биш.

### 2.36 ASYNC + setTimeout — ГҮЙЛТИЙН ТЭМДЭГГҮЙ бол өөр гүйлтэд нөлөөлнө
Хойшлуулсан дуудлага (fetch-ийн `.then`, `setTimeout`) нь хэрэглэгч аль
хэдийн өөр зүйл хийж байхад ажилладаг. Браузерт ХОЁУЛАНГ нь давтав
(2026-09-21):

· Шалгалтын хариултын 240мс таймер нь ШИНЭ шалгалтын `exIdx`-ийг
  ахиулж эхний асуултыг алгасав (`exIdx=1`, «2 / 10», `exLog` хоосон).
· `loadExam()`-ийн fetch нислэг дунд хэрэглэгч нүүр рүү гарсан ч
  `.then` дэх `show('exam')` эргүүлж татав.
· Ярианы таниулт нь `stop()`-ийн дараа ч эцсийн үр дүнгээ хүргэдэг тул
  ДАРААГИЙН картыг хариулж болзошгүй байв.

**Дүрэм:** async/хойшлуулсан ажил бүрт ГҮЙЛТИЙН ТЭМДЭГ. Эхлэхдээ
`const run = ++xRun;`, буцаж ирэхдээ `if (run !== xRun) return;`.
Гарах/дахин эхлэхэд тэмдгийг ахиулна (`exAbort()`, `stopRecog()`).
Ярианы таниулт цуцлахад `stop()` БИШ `abort()` — `stop()` үр дүнг
хүргэсээр байдаг.

**Мөн:** товчийг `disabled` болгосон бол амлалт ямар ч замаар дуусахад
сэргээ; өлгөөтэй fetch-д `withTimeout()` тавь — эс тэгвэл товч мөнхөд
идэвхгүй үлдэнэ.

Регресс: `tools/test_ui.js` §9b «№5», «№6».

### 2.26 PostgREST — функцийн ГАРЫН ҮСЭГ өөрчлөхөд `replace` хүрэлцэхгүй

## 5. Тогтмол хэрэглэдэг командууд

### Supabase — SQL Editor-т хадгалсан асуултууд

| # | Нэр | Юу хийдэг |
|---|---|---|
| 01 | Схем | `SUPABASE.sql`-ийн бүтэн хуулбар. Давтагдахад тэсвэртэй. |
| 02 | Тестийн өгөгдөл цэвэрлэх | Хөгжүүлэлтийн мөрийг устгана. |
| 03 | Хэрэглээний задаргаа | Цаг тутмын шинэ төхөөрөмж. |
| 04 | Ping шалгалт (rollback) | `ping()`-ийн БИЧИХ замыг шалгана. |

`04` нь регресс тест — `ping()`-ийг өөрчлөх бүрд ажиллуулна. Хүлээгдэх
үр дүн **нэг мөр: `1 · 12 · 34 · 5`**. Энэ мөр гурван зүйлийг нэг дор
нотолно: бичих зам ажиллаж байна · `p_bump:false` нь `opens`-ыг
нэмээгүй (2 биш 1) · `greatest()` нь бага тоог үл тоосон (3/4/1 биш).

`begin … rollback` тул хэдэн ч удаа ажиллуулж болно — хуурамч
төхөөрөмж бүртгэгдэхгүй (§2.13-ын алдаанд дахин орохгүй).

```sql
begin;
select public.ping('zzz-verify-0001-test', 12, 34, 5, true);
select public.ping('zzz-verify-0001-test', 3, 4, 1, false);
select opens, cards, answers, learned
  from public.devices where dev = 'zzz-verify-0001-test';
rollback;
```

**Анхаар:** plpgsql функцийн дотоод SQL нь ҮҮСГЭХ үедээ бүрэн
шалгагддаггүй. Баганын нэр буруу байсан ч функц асуудалгүй үүсээд,
зөвхөн АЖИЛЛАХ үед л унана. Тиймээс `create` амжилттай болсон нь
нотолгоо БИШ — бичих замыг заавал дуудаж үз.
