# Мартчихлаа

*Irodori 入門-ийн шинэ үгийг тогтоох хүртэл суллахгүй.*

**PRJ код:** `JPN` · **Төрөл:** статик вэб апп (GitHub Pages) · **Эхэлсэн:** 2026-09-09

Japan Foundation-ы **Irodori** сурах бичгийн *Шинэ үгийн жагсаалт*-ыг Duolingo
маягаар давтах апп. Дуолинго дээр өөрийн үгээ нэмэх боломжгүй тул сурч буй
номтойгоо шууд холбогдсон хувилбарыг өөрөө хийв.

## Гурван үндсэн сонголт

| Хэсэг | Агуулга |
|---|---|
| **Irodori** | Ном → хичээл → «шинэ үг» эсвэл «шинэ ханз» → дасгал |
| **JLPT** | N5–N2 түвшний ханз |
| **Кана** | Хирагана · катакана |

Гурван ном, нийт **4210 үг**:

| Ном | Түвшин | Үг | Ханз |
|---|---|---|---|
| `入門` Суурь шат | A1 | 1232 | 401 |
| `初級1` Анхан шат 1 | A2 | 1192 | 510 |
| `初級2` Анхан шат 2 | A2 | 1786 | 719 |

Ном бүр **тусдаа файлтай** (`data/vocab*.json`) — апп зөвхөн сонгосон номоо
татдаг тул эхний ачаалал хөнгөн. id-ийн угтвар ном бүрд өөр (`L` · `E1` · `E2`)
тул явц хольцолдохгүй.

## Гол зарчим

**Ромажиг хаана ч харуулахгүй.** Үг зөвхөн кана/ханзаар гарна — эс тэгвээс
нүд ромажи руу зугтаж, хирагана/катакана тогтохгүй. «Гараар бичих» дасгалд
хэрэглэгч латинаар бичихэд **шууд кана болж** харагдана (`namae` → `なまえ`),
тиймээс япон IME суулгах шаардлагагүй мөртлөө нүдэнд ромажи үлдэхгүй.

## Дасгалын горим

| Горим | Юу асуух вэ |
|---|---|
| **Флашкарт** | Карт эргүүлж өөрөө дүгнэнэ |
| **Олон сонголт** | 4 хариултаас — сандруулагч нь **сонгосон хичээлээс**, **ойролцоо дуудлагатай** |
| **Гараар бичих** | Монгол → латинаар бичихэд кана болно |
| **Сонсох** | Дуудлагыг сонсоод утгыг таана |

**Чиглэл** сонгож болно: `日本語 → Монгол` (анхдагч) эсвэл `Монгол → 日本語`.
Урвуу чиглэл нь идэвхтэй санах ойг шалгадаг тул хүнд, гэхдээ үр дүнтэй.
«Флашкарт» ба «Олон сонголт» хоёрт үйлчилнэ.

Мөн **кана цээжлэх** дөрвөн дасгал (бүгд 4 сонголттой, 107 кана):

| Горим | Юу асуух вэ |
|---|---|
| `ひらがな → カタカナ` | Хираганаас катаканыг |
| `カタカナ → ひらがな` | Катаканаас хираганыг |
| **Кана → авиа** | Уншлагыг **кириллээр** (`き` → `ки`) |
| **Сонсоод таах** | Дуудлагыг сонсоод канаг |

Бүлгээр нь шүүнэ: `五十音` 46 · `濁音・半濁音` 25 · `拗音` 36.
Авиаг ромажигаар биш **кириллээр** өгсөн — аппад ромажи харуулахгүй зарчимтай нийцүүлэв.

Мөн **ханз цээжлэх** дөрвөн дасгал (**1027 ханз**):

| Горим | Юу асуух вэ |
|---|---|
| **Флашкарт** | Ханз → утга, 音/訓 уншлага, жишээ үг |
| `漢字 → утга` | Ханзыг харж монгол утгыг нь сонгоно |
| `Утга → 漢字` | Утгыг харж ханзыг нь сонгоно |
| **Уншлага** | Ханзны 音読み-г сонгоно |

Хоёр эх сурвалжаас шүүнэ: **сонгосон хичээлүүдэд гарсан ханз** (нийт 401) ба
**JLPT N5 79 · N4 166 · N3 367 · N2 367**.

Сандруулагчийг **ойролцоо уншлагаар** сонгоно — `小`/`少` (хоёулаа ショウ),
`高`/`行` (コウ) зэрэг ханз сурахад тохиолддог жинхэнэ будлиан дээр шалгана.
Монгол утгын үсгийн зайгаар сонговол зөвхөн ижил урттай утга гарч ирдэг тул
хэтэрхий амархан болно.

Ханзны дуудлагад **шинэ бичлэг үүсгээгүй** — жишээ үгийнх нь бичлэгийг
ашиглана. Ганц ханзны дуудлага олон янз байдаг тул үгээр нь сонсох илүү зөв,
бас нэмэлт хэмжээ 0.

Давталт нь **Leitner**-ийн зарчмаар: зөв хариулбал дараагийн хайрцаг руу,
алдвал хоёр хайрцаг ухарна. Хайрцгийн зай — **1 · 3 · 7 · 14 · 30 хоног**.
Явц браузерын `localStorage`-д хадгалагдана (төхөөрөмж бүрд тусдаа), явцаа
`.json` болгон гаргаж/сэргээж болно.

## Төхөөрөмж хооронд нийлүүлэх (заавал биш)

Явц анхдагчаар **зөвхөн тухайн браузерт** хадгалагдана. Утас, компьютер хоёрын
явцыг нийлүүлэхийг хүсвэл Supabase-ийн үнэгүй түвшинг холбоно:

1. [supabase.com](https://supabase.com) дээр төсөл үүсгэ.
2. **SQL Editor** → [`SUPABASE.sql`](SUPABASE.sql)-ыг бүтнээр нь наагаад **RUN**.
3. **Project Settings → Data API** → `Project URL` ба `anon public` түлхүүрийг
   хуулж [`sync-config.js`](sync-config.js)-д тавь. (`service_role`-ыг ХЭЗЭЭ Ч БИШ.)
4. Аппын **Явц** дэлгэц дээр «Шинэ код үүсгэх» → гарсан кодыг нөгөө төхөөрөмж
   дээрээ «Кодоор холбох» дээр оруул.

Тохируулаагүй бол синкийн хэсэг нүүрэндээ огт гарахгүй, апп хэвийн ажиллана.

### Аюулгүй байдал ба нууцлал

- **Хувийн мэдээлэл огт цуглуулахгүй** — и-мэйл ч, нэр ч үгүй. Хадгалагдах
  бүхэн нь: санамсаргүй код, ба «аль үгийг хэдэн удаа давтаж, аль хайрцагт
  байгаа» гэсэн тоо.
- **Код бол нэвтрэлт биш, түлхүүр.** Хэн нэгэн кодыг чинь мэдвэл тэр явцыг
  унших, дарж бичих боломжтой. Тиймээс кодыг апп өөрөө санамсаргүй үүсгэдэг
  (60 бит) — хүн сонговол таахад амархан болно.
- **Хүснэгт рүү шууд хандахыг хаасан.** RLS асаалттай, policy огт бичээгүй тул
  анон түлхүүрээр `select * from progress` хийх боломжгүй. Зөвхөн код авдаг
  хоёр `security definer` функцээр хандана — ингэснээр хэн нэгэн БҮХ хүний
  мөрийг цуглуулж татах боломжгүй.
- **anon түлхүүр public репод харагдах нь хэвийн** — тэр нь зориулалтаараа
  браузерт очдог. Хамгаалалт нь дээрх RLS + функцийн загвараар хийгддэг.

### Нийлүүлэх дүрэм — дарж бичихгүй, УУСГАНА

`id` тус бүрээр **илүү олон удаа давтсан** бичлэгийг авна; тэнцвэл илүү өндөр
хайрцгийг. Ингэснээр утас компьютерийнхээ явцыг (эсвэл эсрэгээр) устгахгүй.
Дасгал дуусмагц болон апп нээхэд автоматаар нийлүүлнэ.

## Санал хүсэлт → GitHub Issue

Аппын доторх «Санал хүсэлт» хэсгээс бичсэн зүйл Supabase-ийн `feedback`
хүснэгтэд орж, `.github/workflows/feedback-to-issues.yml` нэрийн GitHub Action
30 минут тутам түүнийг уншиж **Issue болгон нэмнэ**. Хэрэглэгчид GitHub
бүртгэл хэрэггүй.

**Яагаад аппаас шууд GitHub API руу залгадаггүй вэ.** Тэр нь токен шаарддаг.
Статик сайтад тавьсан токеныг хэн ч задалж авах ба репод дураараа бичих болно.
Тиймээс токен нь зөвхөн GitHub-ийн **шифрлэгдсэн Secrets** дотор, сервер талд
байна.

Тохируулах (нэг удаа):

1. [`SUPABASE.sql`](SUPABASE.sql)-ын **шинэ хэсгийг** SQL Editor-т наагаад RUN.
2. GitHub → **Settings → Secrets and variables → Actions** → хоёр нууц нэмнэ:
   - `SUPABASE_URL` — төслийн URL
   - `SUPABASE_SERVICE_KEY` — Supabase → API keys → **`service_role`**
3. Actions таб дээр `feedback-to-issues`-ыг нэг удаа гараар ажиллуулж шалгана.

> `service_role` түлхүүр нь бүх хамгаалалтыг тойрдог. Түүнийг **зөвхөн**
> GitHub Secrets дотор хийнэ — репод бичихгүй, хэнд ч илгээхгүй.
> Тохируулаагүй байхад апп хэвийн ажиллана: «Илгээх» товч ажиллахгүй ч
> GitHub дээр шууд бичих холбоос нь бичсэн зүйлээр урьдчилан дүүрч гарна.

**Спамаас сэргийлэлт:** нэг төхөөрөмж 10 минутад 3-аас олон илгээхгүй, урт нь
2000 тэмдэгтээр хязгаарлагдана — хоёулаа өгөгдлийн сангийн функц дотор.

## Хэрэглээний тоо

Профайл дээр «Хэрэглээ» хэсэг: төхөөрөмжийн тоо, 7 хоногт идэвхтэй, нийт
нээлт, санал хүсэлтийн тоо. Апп нээгдэхэд **өдөрт нэг удаа** `ping` дуудна.

Хадгалагдах бүхэн: браузерын localStorage-д үүссэн **санамсаргүй төхөөрөмжийн
id**, огноо, тоо. IP ч, хэрэглэгчийн агент ч, хувийн мэдээлэл ч хадгалахгүй.
`usage_stats()` нь зөвхөн **нийлбэр тоо** буцаана — хэний ч мөр гарахгүй.

## Дуудлага

Үг бүрийн дуудлагыг **урьдчилан бэлдсэн** — `audio/<id>.mp3`. Файл байвал үргэлж
түүнийг тоглуулж, зөвхөн байхгүй үед л браузерын `speechSynthesis` рүү шилжинэ.

### Яагаад TTS биш вэ

1. Гар утсан дээр `speechSynthesis` **найдваргүй** — систем япон хоолойгүй бол чимээгүй.
2. Ерөнхий TTS нь **өргөлтийг буруу** уншдаг (`ミャンマー` [1]-ийг тэгш уншиж мэднэ).
3. Офлайн ажиллахгүй.

### Яагаад Irodori-гийн албан ёсны бичлэг биш вэ

[Тэдний бичлэг](https://www.irodori.jpf.go.jp/wordlists/audio/starter_01.html) байдаг ч
Japan Foundation-ы ашиглалтын нөхцөл нь *"may not be reproduced, copied, or altered ...
other than for private use or use by schools"* гэдэг — **нээлттэй репод дахин
байршуулах эрхгүй**. Мөн тэдний файл нь үг тус бүрээр биш, хичээлийн хэсгээр байдаг.

### VOICEVOX

Дуудлагыг [VOICEVOX](https://voicevox.hiroshiba.jp/)-оор үүсгэсэн (`tools/build_audio.py`).
Гол давуу тал нь **өргөлтийн байрлалыг гаднаас авдаг**: номноос задалсан `↓ ○`
тэмдэглэгээг «AquesTalk風記法» болгож хөрвүүлээд хөдөлгүүрт өгснөөр өргөлт **номтой
яг таарна**. Ном тэмдэглээгүй хэсэгт хөдөлгүүрийн өөрийн толийг ашиглана.

Хэрэгжүүлэлтийн гурван нарийн зүйл:

- `平板型`-ыг **сүүлийн мора дээрх унал** болгон бичдэг. Ганцаараа дуудахад авиа
  зүйн хувьд ижил — ялгаа нь зөвхөн дараагийн нөхцөлт үг дээр гардаг.
- AquesTalk бичлэг `ー`-г **хүлээж авдаггүй** (`UNKNOWN_TEXT`). Уртатгалыг өмнөх
  морагийн эгшгээр солино: `ミャンマー` → `ミャンマア`.
- `／ （） △` дээр тасалж, тус бүрийг **тусдаа өргөлтийн хэсэг** болгоно.

**Кредит (лицензийн шаардлага):** `VOICEVOX:四国めたん`

### Хуучин арга (нөөц)

Бичлэг байхгүй үед браузерын `speechSynthesis`-ийг ашиглана.

- **Флашкарт · олон сонголт · сонсох** горимд карт гармагц дуудлага
  автоматаар сонсогдоно. 🔊 товчоор дахин сонсоно.
- **Гараар бичих** горимд урьдчилж сонсгохгүй, 🔊 товч ч нуугдана — асуулт нь
  монгол утга, хариулт нь япон үг учраас сонсговол хариултыг задалж өгнө.
  Хариулсны дараа сонсогдоно.

Гар утсан дээр анхаарах хоёр зүйл кодод тусгагдсан:

- `getVoices()` нь утсан дээр **хойшлон** дүүрдэг. Хоолой олдох хүртэл хүлээж
  товчийг нуувал хэзээ ч гарч ирэхгүй тул `speechSynthesis` байгаа бүх үед
  товчийг харуулж, `onvoiceschanged` дээр дахин шинэчилдэг.
- Ихэнх утас эхний дуу гаргахын өмнө **хэрэглэгчийн хүрэлт** шаарддаг —
  эхний хүрэлт дээр чимээгүй utterance явуулж түгжээг тайлдаг.

Яг таарсан `ja` хоолой олдоогүй ч `lang="ja-JP"` гэж өгдөг тул систем өөрөө
япон хоолой сонгоно. Windows дээр огт байхгүй бол:
`Settings → Time & language → Language & region → 日本語 нэмэх → Language options → Speech`.

## Ажиллуулах

GitHub Pages дээр шууд нээгдэнэ. Локалаар үзэх бол — `file://`-ээр нээвэл
браузер `fetch`-ийг хориглодог тул жижиг сервер хэрэгтэй:

```
cd 82-irodori-web
python -m http.server 8765
# http://localhost:8765
```

Гүн холбоос: `index.html#m=type` (`flash` · `choice` · `listen`) эсвэл
`index.html#k=h2k` (`k2h` · `sound` · `klisten`) — шууд тэр горимоор эхэлнэ.
`&s=kana` нэмбэл үгийг канагаар, `&d=mn2jp` нэмбэл урвуу чиглэлээр асууна.

Дууг дахин үүсгэх (VOICEVOX хөдөлгүүр ажиллаж байх ёстой):

```
python tools/build_audio.py --list-speakers
python tools/build_audio.py --speaker 2
```

### Өгөгдөл хэрхэн гарсан бэ

PDF-ийн хавтгай текст дамп дээр **багана холилддог** (жишээ нь L2-т монгол
утгууд блокийн төгсгөлд бөөгнөрдөг). Тиймээс `PyMuPDF`-ээр span бүрийн
`x, y`, фонтын хэмжээ, өнгийг уншиж 4 баганыг сэргээв:

| Багана | `x0` | Фонт |
|---|---|---|
| `ことば` | 62–76 | 12.0 |
| `ローマ字` | 205–207 | 8.0 |
| `アクセント` | 301–306 | 9.0 |
| Монгол | 417–429 | 9.0 |

### 初級1 · 初級2 нь өөр бүтэцтэй

`入門` нь **4 баганатай** (`ことば · ローマ字 · アクセント · Монгол`), харин
`初級1/2` нь **ромажигүй 3 баганатай** бөгөөд фуригана нь үгийн дээр тусдаа
5.0 фонтоор ордог. Тиймээс `extract_vocab.py` нь номын тохиргооны хүснэгттэй
(`BOOKS`) — баганын хил, фонтын хэмжээ, хуудасны хязгаарыг ном бүрд өөр өгнө.

Хоёр нарийн зүйл нэмж илэрсэн:

- **Хүснэгтийн толгой мөр** (`ことば`) нь үгтэй ижил хэмжээтэй боловч **цагаан**
  өнгөтэй — үүгээр нь ялгаж хассан. Бүлгийн гарчиг ч цагаан ч тэр нь илүү том
  фонттой тул зангуу болдоггүй.
- **Лавлах үг хоёр өнгөтэй**: саарал `#9D9FA2` = `参考語彙`, харин `#808A85`
  = `会話練習`-ийн болон уншлагын нэмэлт үг. Номын тайлбар хуудсанд тодорхойлсон.
  Хоёуланг нь «лавлах» гэж тэмдэглэв (el1 195 · el2 434).

Задлалтын чанар: `入門` 9 асуудал · `初級1` **0** · `初級2` 2.

### 入門-ийн гурван нарийн зүйл

- **Багана зөвхөн `x`-ээр таарахгүй.** Зарим монгол нүд 414-өөс зүүн тийш
  эхэлдэг тул кирилл эсэхээр нь ялгасан.
- **Урт үг `ローマ字` зурваст халидаг** — 12.0 фонт ба кана бичгээр ялгасан.
- **Нүд 2 мөр болж уншигдана** (`着替える／` + `着替えます`). Үргэлжлэл мөрөнд
  ромажи ч, утга ч байхгүй байдаг — үүгээр нь таньж нийлүүлсэн.

Өргөлтийн `↓○△` тэмдгийг салгаж **цэвэр кана уншлага** гаргасан — энэ нь
бичих дасгалын хариулт болно. Өргөлтийн тэмдэглэгээ нь хариулт дээр харагдана.

## 3D үгийн цагираг

Нүүр ба сонголтын дэлгэцүүд дээр үгийн сангаас түүсэн 14 карт удаан
эргэлдэнэ (`#ring`). Дасгал эхлүүлэхэд урд талын карт сугарч, дасгалын
картын байрлал руу нисэж томордог. Нисдэг карт нь **яг тэр дасгалд гарах
үгийг** харуулна — `enterStudy()` нь `queue[0]`-ийг уншина.

Цагираг НЭГ л ширхэг бөгөөд идэвхтэй дэлгэцийн `.ringslot` руу зөөгдөнө.

Хажуугаар нь бүх дэлгэцийн ард загвар тус бүрийн дүр хөдөлнө (`#bg`):
сансарт од ба мананцар, тэнгэрт гурван давхарга үүл, усанд урсгал,
борооны шилэн дээр дусал гулсана.

**Профайл → Хөдөлгөөн** дээрээс унтраана. Системийн
`prefers-reduced-motion: reduce` нь тохиргооноос дээгүүр — заасан бол
ямар ч тохиолдолд хөдөлгөөнгүй. Хоёулаа зөвхөн чимэглэл: алга болсон ч
апп бүрэн ажиллана.

## Загвар (theme)

**Профайл → Загвар** дээрээс дөрвөн загварын аль нэгийг сонгоно.
Загвар бүр өөрийн МАТЕРИАЛД тохирсон `feTurbulence` бүтэцтэй —
гөлгөр градиент, жигд давталт хоёр нь зохиомол харагдуулдаг.
Сонголт `localStorage`-д (`irodori.theme.v1`) хадгалагдана.

| Түлхүүр | | Нэр | Ямар вэ |
|---|---|---|---|
| `blue` | 蒼 | Цэнхэр | Гүн ус · удаан урсгал · тайван. **Анхдагч** |
| `space` | 宙 | Сансар | Од, мананцар · гүн хөх · хөвөгч хавтан |
| `anime` | 空 | Аниме | Цэлмэг тэнгэр · хөвөх үүл · поп ягаан |
| `rain` | 雨 | Бороо | Үүлэрхэг саарал · норсон шил · урсах дусал |

Загвар бүр НЭГ өнгөний схемд амлалт өгнө — тус бүрийг цайвар/харанхуй
болгож үржүүлбэл арван палитр болж, аль нь ч сайн болохгүй. Тиймээс
системийн `prefers-color-scheme` дагахаа больсон.

`app.css` нь БҮТЭЦ ба **цэнхэр**-ийг агуулна; `themes.css` нь
`html[data-theme=…]` дээрх **токеныг** л дарж бичнэ. Тиймээс шинэ
загвар нэмэх нь ~40 мөр бөгөөд марк-ап хөндөгдөхгүй.

Хэлбэрийн токенууд: `--box-bg` `--box-bd` `--box-r` `--box-sep`
`--box-pad` `--list-gap` `--list-top` `--elev` `--r` `--btn-bg/fg`
`--sel-bg/fg` `--h2-tt/ls/bd` `--track-h` `--grain` `--fx1..3` `--fx-op`
`--mono`.

Сонгосон загварыг `index.html`-ийн `<head>` доторх эрт скрипт тавина —
`app.js` дотор тавибал хуудас эхлээд анхдагчаар анивчина.

## Фонт — яагаад өөрсдөө нийлүүлэв

Хоёр шалтгаан, хоёулаа **гоо сайхны биш, ЗӨВ ХАРАГДАХ** асуудал:

1. **Монгол Ү (U+04AE) ба Ө (U+04E8)** нь Windows-ийн олон фонтод
   БАЙХГҮЙ. Шалгасан — serif: `Georgia` · `Times New Roman` ·
   `Palatino Linotype` · `Cambria` · `Constantia`; монспэйс:
   `Consolas` · `Cascadia Mono` · `Courier New`. Бүгд дутуу. Тэдгээр
   үсэг өөр фонтоос орлогдож, «ҮГНИЙ» гэсэн үгийн дунд хоёр өөр
   загварын үсэг холилдоно; монспэйс дээр эгнээ ч эвдэрнэ.
2. **明朝 (Yu Mincho)** нь зөвхөн Windows/Mac дээр бий. Android дээр
   байхгүй тул хэрэглэгчдийн ихэнх нь өөр загварын япон бичиг харна.

Тиймээс `tools/build_fonts.py` нь өгөгдөл ба марк-апаас тэмдэгтийг
цуглуулж (1577 япон + 182 латин/кирилл) Google Fonts-оос яг тэр
тэмдэгтээр огтолсон `woff2` татна:

| Фонт | Юунд | Хэмжээ |
|---|---|---:|
| **Noto Sans Mono** | Синкийн код, оношилгооны гаралт (`--mono`) | 11 КБ |
| **Noto Serif JP** | Япон бичиг (бүх загварт нэгэн ижил) | 348 КБ |

Бүтэн Noto Serif JP нь ~5 МБ. Sans (Segoe UI, system-ui) нь Ү/Ө-тэй
бүрэн тул татах шаардлагагүй.

Google-ийн `text=` параметр **URL хэт урт болвол ЧИМЭЭГҮЙ үл тоогддог** —
1568 тэмдэгт өгөхөд огтолсон нэг файлын оронд бүтэн фонтыг 124 хэсгээр
буцаана. Тиймээс скрипт нь 300 тэмдэгтийн багцаар хүсэлт тавьж, буцах
файлын тоог шалгана.

Фонтууд `sw.js`-ийн `CORE` жагсаалтад орсон тул офлайн үед ч ижил харагдана.

## Офлайн

`sw.js` нь хоёр кэш хөтөлнө: `shell-<хувилбар>` (index/app/өгөгдөл) ба `media-v1`
(mp3). Дууны файл нь id тутамд нэг, агуулга нь хэзээ ч өөрчлөгддөггүй тул хувилбар
солигдоход дахин татагдахгүй. Аппын файлд **сүлжээ эхэлж** ажиллана — service

Профайл → «Бүх дууг офлайнд татах» дарвал бүх бичлэгийг урьдчилан хадгална.
